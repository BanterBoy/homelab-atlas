# v0.6.0

Atlas can now review Docker services from an optional restricted collector or a sanitized snapshot file. Discovery never starts automatically. Every finding begins unchecked, and you choose whether to add it or link it to an existing service.

Links preserve the existing service name, logo, count, group, order, and card. Additions preserve every existing card position and width, show required height growth before applying, and stop if the newly grown strip would collide with another card. A new Docker card is placed below existing cards. The complete review is one undoable change.

The normal editor container still has no Docker socket. The optional `discovery` Compose profile runs the same image as a separate authenticated collector with a read-only socket, no published port, an internal network, a read-only filesystem, dropped capabilities, and `no-new-privileges`.

The runtime is now one Go standard-library binary with embedded editor assets. It provides the default server plus `healthcheck` and `collect` commands. Compressible assets reuse smaller gzip representations prepared at startup and use encoding-specific ETags with revalidation. Published images remain available for Linux AMD64 and ARM64.

Atlas 0.6 saves schema-version-5 projects. Schema versions 1 through 4 import automatically after validation. Existing inventory, custom logos, and manual layouts are preserved. Schema version 5 stores only stable discovery bindings, not raw snapshots, collector URLs, or tokens.

Install v0.6.0:

```sh
curl -fsSLO https://github.com/aiden0rchad/homelab-atlas/releases/download/v0.6.0/compose.release.yaml
docker compose -f compose.release.yaml up -d
```

To enable local Docker discovery, generate a token with `openssl rand -hex 32`, save it as `ATLAS_COLLECTOR_TOKEN` in `.env`, then run:

```sh
docker compose -f compose.release.yaml --profile discovery up -d
```

Read [Docker discovery](/discovery) before configuring a remote collector or remote editor access.
